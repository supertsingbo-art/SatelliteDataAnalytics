- 周期：10 周
- 团队规模：8-10 人
- 单位：人天（PD）
- 估算口径：含需求、开发、自测、联调、文档；不含长期运维
- 风险缓冲：15%

- Mongo 到 ClickHouse 数据链路：28 PD
- 任务调度与治理（Hangfire）：24 PD
- 算法处理模块（内置）：30 PD
- 一致性比对模块：20 PD
- 报告引擎（Word+模板）：24 PD
- 对象存储（MinIO/S3兼容）：12 PD
- 前端页面（任务/模板/报告）：46 PD
- 联调与系统测试：30 PD
- 性能与稳定性专项：16 PD
- 部署与可观测性：14 PD
- 文档与验收支持：12 PD

- 9 人全职 10 周理论产能：450 PD

## 6. 风险清单与缓解措施
- 规则口径频繁变更
  - 缓解：每周规则评审，模板版本冻结机制
- 长任务超时与资源争抢
  - 缓解：按队列隔离并发，任务分片，8小时超时强管控
- 数据规模引发性能风险
  - 缓解：早期压测，ClickHouse 分区与排序键先定型
- 可追溯链路不完整
  - 缓解：强制记录模板版本、任务批次、时间窗、操作者
- 上传算法带来安全风险
  - 缓解：沙箱隔离、禁网策略、资源上限、审计日志
- 报告模板复杂度过高
  - 缓解：先定义模板规范与校验器，限制一期模板能力
- 跨库一致性风险
  - 缓解：任务状态机 + 幂等键 + 失败补偿机制

## 7. 管理建议
- 固定三类周评审：规则评审、技术评审、验收评审
- 每周至少一次端到端演示（模板到报告）
- 验收用例先行，开发与测试同口径推进

## 8. 一期范围控制建议
- 编排 UI 一期先线性流程，分支/循环/并行后续增强
- 用户上传算法能力建议一期后段灰度开启
- 优先保证：可追溯、可重跑、可出报告三条主线
- 第三方开放 API 与 Webhook 建议**二期或一期末迭代**，需求与表结构见《PostgreSQL元数据与对外接口设计说明》
